# 知识搜集方案 · 产品通用轨（v2.2）

> 适用于 REQ、BIZ、SYS、DAT、GRO、STR、UXD、DLV、LCM 九个领域。AI 轨继续沿用 GitHub 采集程序与 `资料库\`。
> 搜集到的每条素材都要做成「素材卡」，格式与整合流程见 `碎片内容整合规则.md`。

## 一、为什么不沿用 GitHub 采集程序

采集程序按「近期 Star 增长」发现热门 AI 项目。通用产品知识有三个不同：

1. **知识稳定**：需求分层、BPMN、RBAC、北极星指标十几年都没变，按热度追新没有意义。
2. **来源不在 GitHub**：权威来源是标准、教材、产品官方文档和真实项目经验，不是代码仓库。
3. **重准确不重新鲜**：基础题的价值在于定义和机制讲对，需要的是可核对的来源。

所以产品通用轨用「**人工 + AI 研究助手**」按概念清单定向搜集，存进 `素材库\`。只有少数拓展题和案例题会借用 GitHub 上的开源业务系统（例如已收录的 `n8n-io/n8n`），这部分仍从 `资料库\` 读原文。

## 二、五类来源与用途

| 类别 | 来源 | 用来写什么 | 可信度 | 使用限制 |
|---|---|---|---|---|
| **A 权威骨架** | 标准与知识体系、经典教材、厂商官方文档 | 基础题的定义、机制、术语；`concept` 和 `basics` 的事实依据 | 高 | 只摘 1–2 句原文，其余用自己的话改写 |

## 三、搜集流程（每个领域一轮）

1. **锁定概念清单**：以 `通用PM领域_扩展方案.md` 第七节的概念键为准，每个概念就是一个搜集单元。
2. **列缺口表**：为每个概念记下已有素材卡数量和类别，对照第四节的够料标准找缺口。
3. **定向搜集**：
   - A 类：先查第二节的权威来源，记下书名或标准名、章节、版本。
   - C 类：只为规划了案例题的概念找，一个案例题配一个真实产品。
   - B 类：每个领域安排一次 20–30 分钟的「经历回忆」，用 STAR 结构快速写下来（可以口述给 AI，让它整理成素材卡）。
   - D 类：每个领域看 5–10 份目标岗位 JD，统计被要求的能力关键词。
4. **用 AI 研究助手补全**：让 AI 按概念做专题检索，**要求每条结论附来源链接或书目章节**，输出直接按素材卡格式。AI 给出的、没有来源的说法一律当作待核实，不进卡片正文。
5. **入库**：所有卡片先进 `素材库\_收件箱\`，再按整合规则归档、去重、裁决冲突。
6. **够料检查通过后**，才进入该领域的出题规划。

## 四、够料标准（进入出题的门槛）

| 题目类型 | 最低素材要求 |
|---|---|
| 基础题（F, knowledge） | 该概念至少 1 张 A 类卡，并含一个可用的生活化例子 |
| 拓展题 idea / method | 至少 1 张 A 类卡 + 1 张 B 或 C 类卡；如果是取舍题，要有两种不同立场的来源 |
| 案例题 case | 至少 1 张 C 类卡（公开资料）；用你的经历作案例时，要 1 张已脱敏的 B 类卡并经你本人确认 |
| 带数字的说法 | 两处独立来源一致，否则不写具体数字 |

## 五、隐私、保密与版权

- **保密协议优先**：实习单位的内部系统名称、客户名称、未公开数据、内部流程文档、截图一律不收。拿不准的先不收，默认不能用。
- **脱敏写法**：客户写成「某连锁健身品牌」「某头部券商」；系统写成「客户服务管理平台」「工单系统」；数字只保留量级或比例，且不能反推出原值。
- **个人信息**：不收任何同事、客户的姓名、联系方式、可识别细节。
- **版权**：书籍与付费内容每张卡最多摘 2 句原文，其余必须是自己的话；题目正文不出现大段转述。
- **面经与 JD**：只记录题目和能力关键词，不复制原帖全文。

## 六、节奏建议

- 第一批（REQ、BIZ、SYS）：每个领域约 30–40 张卡，搜集一周、出题与审题一周，三个领域约六周。
- 搜集与出题可以错开：A 领域出题时，B 领域在搜集。
- 平时遇到的零散内容（文章、课堂笔记、面试被问到的题）随手丢进 `_收件箱\`，每周整理一次。
