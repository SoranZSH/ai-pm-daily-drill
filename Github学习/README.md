# Github学习

产出学习内容的项目：把 AI 领域的通用知识、思想、方法、案例整理成题库，供「每日一题」提醒程序（上一级文件夹 `面试英语题库`）每天推送练习。GitHub 热门项目是题目素材的来源之一：采集程序每天巡检，结果同时进入 `采集包/`（出题用）和 `资料库/`（长期原料库）。

两个项目**只通过一个文件夹和两种文件格式相连**，各自可以独立修改。

```
【Github学习 · 出题】
  任何来源（手写 / AI 生成 / 采集包）
      ↓ 按《题库编写规范》输出
  题库更新_YYYYMMDD.json        ← 契约①：更新文件（v2，新题只写临时编号 N1、N2…）
      ↓ 双击 题库更新.exe：校验 → 选【增量添加】/【题库覆盖】→ 分配正式题号 → 预览 → 备份 → 写入
  当前题库/*.json               ← 契约②：题库文件（v2，含层级 F/X、前置 prereq、导入日期 added）
      ↓ 只读（位置由 面试英语题库\题库路径.json 指定）
【面试英语题库 · 练题】
  到期复习 → 新导入且前置已练完的题 → 其他已解锁的题；学习记录留在那边
```

## 目录

| 路径 | 作用 |
|---|---|
| `当前题库/` | **题库本体**，每个分类一个 JSON。只通过 exe 修改，不要手改 |
| `题库更新.exe` | 导入工具（源码在 `工具源码/题库更新/`；公开仓库不含 exe，用 `go build` 编译或从 Releases 下载） |
| `题库目录.md` | exe 每次导入后自动生成的现有题目清单，出题时发给 AI 用来挂前置、避免重复 |
| `题号登记.json` | exe 记录每个「领域-层级」用过的最大序号，保证题号永不重复使用。不要手改 |
| `资料库/` | 采集程序收录的 AI 项目原料，一项目一文件，面向 AI 产品经理的基础知识学习；用法和给 Agent 的提炼提示词见其中的 README。公开仓库只含索引，项目原料（第三方 README 全文）在本机生成 |
| `collector/` | 采集程序（定时巡检，`collect.py --init` 为初始化模式） |
| `采集包/` | 每次巡检的结果包（出题用），旧包可手动删除；运行产物，不进仓库，节选见根目录 `examples/` |
| `开发记录/` | 开发过程中的决策记录、审阅报告与自检报告 |
| `素材库/` | 通用产品领域（需求、业务架构、定价、生命周期等）的整理笔记，供出题引用 |
| `知识地图.json` | 概念键定义（如 `rag.embedding`），题目的 `concepts` 字段引用它；可手动增补 |
| `题库模板/` | 更新模板、《题库编写规范》（v2.1）、出题提示词（重建 / 采集包 / 通用 PM）、审题提示词、通用 PM 领域扩展方案 |
| `题库备份/` | 每次导入前的完整备份（含题号登记），保留最近 20 份；运行产物，不进仓库 |
| `已导入/` | 导入成功的更新文件，以及对应的「题号对照」；运行产物，不进仓库 |
| `AI实践采集与题库生成_方案设计.md` | 采集程序与整体设计的可执行方案（M0–M6） |
| `GitHub多语言热点监测_项目说明与概要设计.md` | 远期的热度预测模型设计 |

## 两份契约

**契约①：更新文件**（`题库更新_YYYYMMDD[_n].json`，`format: interview-bank-update/v2`）

- 新题写临时编号 `ref`（N1、N2…），不写 `id`；改题写原题号 `id`；删题写进 `delete_ids`。
- 正式题号由 exe 分配，格式 `领域-层级+序号`，如 `AGT-F001`（基础）、`AGT-X003`（拓展）。
- 导入时选择【增量添加】（在现有题库上改）或【题库覆盖】（整体替换，只能包含新题）。
- 详细规则见 `题库模板/题库编写规范.md`。

**契约②：题库文件**（`当前题库/*.json`）

- 每个分类一个文件：`{"category", "category_en", "domain", "items": [...]}`。
- 每道题必有：`id`、`level`（F/X）、`kind`（knowledge/idea/method/case）、`difficulty`、`tags`、`concepts`、`prereq`、`q_cn`、`q_en`、`concept`、`a_en`、`a_cn`、`key_phrases`、`approach`、`tips`、`added`；可选 `source_repos`。
- 拓展题（X）的 `prereq` 至少含一道基础题（F）。每日一题只在前置题全部练完后才推送它。
- 题号一经分配不会改作他题，也不会在删除或覆盖后被重新使用：每日一题的学习记录按题号记。

每日一题只读契约②；本项目的程序（exe、以后的采集程序）也只读写本文件夹，**不读取每日一题的学习记录**。因此本项目只能知道某个知识点「已出题」，不能声称你「已掌握」。

## 常用操作

| 想做什么 | 怎么做 |
|---|---|
| 看现有题目、下一步该补什么 | 双击 exe（根目录没有更新文件时会显示概览并刷新 `题库目录.md`） |
| 让 AI 写一批新题 | 用 `题库模板/出题提示词_重建题库.md`（先规划、再逐个领域写），写完用 `审题提示词.md` 在新对话里独立审一遍 |
| 换题库位置 / 改文件夹名 | 改 `面试英语题库\题库路径.json` 的 `bank_dir`；exe 这边在旁边放 `题库更新配置.json` 写 `{"bank_dir": "..."}` |
| 导错了 | 从 `题库备份/最新时间戳/` 把 JSON 拷回 `当前题库/`，`_登记/题号登记.json` 拷回本文件夹 |
| 重新做一次大规模初始化 | 在 `collector/` 执行 `python collect.py --init --days 90 --scale 5`（需设置 GITHUB_TOKEN；会跳过「20 小时内已运行」的限制） |
| 让 Agent 提炼学习材料 | 把 `资料库/README.md` 里的提示词连同若干项目文件交给它 |
| 重新编译 exe | 在 `工具源码/题库更新/` 执行 `go test ./...`，通过后 `go build -ldflags "-s -w" -o ..\..\题库更新.exe .` |
